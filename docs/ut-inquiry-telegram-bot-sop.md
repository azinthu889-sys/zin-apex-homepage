# UT 派遣 — အလုပ်ခေါ်စာ → လူခေါ် → လူခန့် | Telegram Bot Workflow & SOP

**စာရွက်အမျိုးအစား:** Design / SOP (v1.1 — draft, code မပါ)
**ပိုင်ရှင်:** Zin Apex Education (ZAE)
**လုပ်ငန်းပုံစံ:** 派遣 (dispatch) — အလုပ်ခေါ်စာ (案件/オーダー) ရရှိ → လူခေါ် (募集) → အလုပ်အကြောင်း ရှင်းပြ (仕事説明) → လူခန့် (採用) → 入社/配属
**ဘာသာစကား (user ဘက်):** မြန်မာ only

> ⚠️ `【要確認】` မှတ်ထားသည့် နေရာတိုင်း — UT ဘက် (သို့) ရုံးနှင့် အတည်ပြုပြီးမှသာ bot ထဲ ထည့်ရမည်။ မသေချာသေးသည့် အချက်အလက်ကို bot က မဖြေရ။

## 1. ဤစနစ်က ဖြေရှင်းပေးမည့် ပြဿနာ

派遣 လုပ်ငန်းတွင် အနိုင်ရ/ရှုံးသည့် အချက်မှာ **အလုပ်ခေါ်စာ ရပြီးနောက် ဘယ်လောက် မြန်မြန် လူပြည့်နိုင်လဲ** ဆိုသည့် တစ်ချက်တည်း ဖြစ်သည်။

လက်ရှိ ပြဿနာ (ပုံမှန် တွေ့ရသည့်):
- အလုပ်ခေါ်စာ ရလာလျှင် — အရင်က ဆက်သွယ်ဖူးသူတွေကို တစ်ယောက်ချင်း ပြန်လိုက်ရှာရသည်၊ ဘယ်သူက ဘယ် visa နဲ့ ဘယ်နားမှာ ရှိလဲ မှတ်မိရန် ခက်
- စိတ်ဝင်စားသူတွေ ဝင်လာလျှင် — အလုပ်အကြောင်း တစ်ယောက်ချင်း ထပ်ခါထပ်ခါ ရှင်းပြနေရသည်
- ဘယ်သူက ဘယ်အဆင့်မှာ ရှိလဲ (မေးဆဲ / လျှောက်ပြီး / 面接 စောင့် / 採用) ခြေရာ ပျောက်သွားသည်
- ခေါ်စာ ပိတ်ရက် လွန်မှ လူ မပြည့်မှန်း သိရသည်

ဤ bot က ဖြေရှင်းသည့် နည်း:
1. **人材プール (လူစာရင်း) ကို ကြိုတင် စုထား** — ခေါ်စာ မရသေးခင်ကတည်းက
2. ခေါ်စာ ရလာလျှင် — **ကိုက်ညီသူများကိုသာ ချက်ချင်း broadcast** (visa/နေရာ/ဂျပန်စာ ဖြင့် စစ်ထုတ်ပြီး)
3. အလုပ်အကြောင်း ရှင်းပြချက်ကို **案件 card တစ်ခုတည်းဖြင့် တစ်ပြေးညီ** ပို့
4. 応募 → 面接 → 採用 အဆင့်တိုင်း **ခြေရာခံနိုင်** ရန် status ထား

## 2. လုပ်ငန်း Cycle — Bot က ဘယ်နေရာမှာ ဝင်လာလဲ

```
┌─ [UT/客先] အလုပ်ခေါ်စာ (案件) ရရှိ
│
├─ ① 案件登録 ........... ဝန်ထမ်း က Notion 案件DB ထဲ သွင်း        [လူ]
│
├─ ② マッチング ........ Bot က 人材プール ထဲမှ ကိုက်ညီသူ စစ်ထုတ်   [Bot]
│
├─ ③ 募集配信 .......... ကိုက်ညီသူများထံ 案件 card ပို့             [Bot]
│                        + Job Channel မှာလည်း တင်
│
├─ ④ 応募受付 .......... "လျှောက်မယ်" နှိပ် → 応募 မှတ်တမ်း ဖွင့်   [Bot]
│                        မကိုက်သေးသူ → 人材登録 flow သို့
│
├─ ⑤ 仕事説明 .......... အလုပ် အသေးစိတ် ရှင်းပြ + နားလည်မှု အတည်ပြု [Bot]
│                        → မေးခွန်း ရှိလျှင် ဝန်ထမ်းသို့ (お問い合わせ) [လူ]
│
├─ ⑥ 選考/面接 ......... ဝန်ထမ်းက ချိန်းဆို → ရလဒ် သွင်း            [လူ]
│                        Bot က သတိပေး (前日/当日)                  [Bot]
│
├─ ⑦ 採用可否 .......... 採用 / 不採用 အကြောင်းကြား                [Bot+လူ]
│
├─ ⑧ 入社手続き ....... စာရွက်စာတမ်း · 就業条件明示 · 入社日        [လူ]
│
└─ ⑨ フォロー .......... 入社後 3日 / 2週 / 1ヶ月 အခြေအနေ မေး       [Bot]
                         ပြဿနာ ရှိလျှင် → お問い合わせ ticket        [လူ]
```

**မှတ်ချက်:** ①⑥⑧ က လူသား လုပ်ရမည့် အဆင့်များ။ Bot က ကျန်အဆင့်များတွင် ထပ်ခါထပ်ခါ လုပ်ရသည့် အလုပ်များကို ယူသွားသည်။ Bot က **ဆုံးဖြတ်ချက် မချရ** — အချက်အလက် သယ်ပေးရုံသာ။

## 6. 人材登録 — လူစာရင်း သွင်းခြင်း (`REGISTER`)

ဤအဆင့်သည် **စနစ်တစ်ခုလုံး၏ အနှစ်သာရ**။ ဤ pool ကြီးလေ ခေါ်စာ ရလာချိန် မြန်လေ ဖြစ်သည်။

### 6.1 လမ်းကြောင်း ခွဲခြင်း (ပထမဆုံး မေးခွန်း)
```
လက်ရှိ ဘယ်မှာ ရှိနေပါသလဲ?
  🇲🇲 မြန်မာနိုင်ငံမှာ ရှိတယ်       → Route A
  🇯🇵 ဂျပန်မှာ ရှိပြီးသား            → Route B
```

**Route B ဆက်မေးရမည်:** လက်ရှိ 在留資格 ဘာလဲ? + 満了日 ဘယ်တော့လဲ?
> ⛔ Bot က "ဒီ visa နဲ့ ရတယ်/မရဘူး" ဟု **မဆုံးဖြတ်ရ**။ စာရင်းသာ ရွေးခိုင်းပြီး ဝန်ထမ်းသို့ လွှဲရမည်။ ဤနေရာ မှားလျှင် နောက်ပိုင်း အလုပ်အားလုံး အလဟဿ ဖြစ်သည်။

## 7. 案件 配信 — အလုပ်ခေါ်စာ ဖြန့်ခြင်း

### 7.1 ဝန်ထမ်း ဘက် (case အသစ် ဝင်လာလျှင်)
1. Notion `案件 DB` ထဲ သွင်း → Status `募集中`
2. Bot က matching စစ်ထုတ်ပြီး ကိုက်ညီသူ အရေအတွက် ပြန်ပြ:
   ```
   案件 UT-2608-001 — ကိုက်ညီသူ 34 ဦး တွေ့ပါတယ်
   🇯🇵 ဂျပန်တွင် 28 ဦး / 🇲🇲 မြန်မာတွင် 6 ဦး
   ▸ ပို့မလား? [✅ ပို့မယ်] [👀 စာရင်း အရင်ကြည့်မယ်] [❌ မပို့သေးဘူး]
   ```
3. ဝန်ထမ်း `✅` နှိပ်မှသာ ပို့ရမည် — **auto မပို့ရ**။ 案件 card မှားနေလျှင် ပြန်ရုပ်သိမ်း၍ မရ။

### 7.2 Matching Rule
| အဆင့် | စစ်ထုတ်ချက် | ကျော်လွှားနိုင်? |
|---|---|---|
| 1 | 在留資格 ကိုက်ညီ | ❌ မကျော်ရ |
| 2 | Status = `求職中` | ❌ မကျော်ရ |
| 3 | 就業可能日 ≤ 案件 入社日 | ⬜ ဝန်ထမ်း ဆုံးဖြတ် |
| 4 | ဂျပန်စာ အဆင့် ≥ လိုအပ်ချက် | ⬜ ဝန်ထမ်း ဆုံးဖြတ် |
| 5 | နေရာ ကိုက်ညီ (သို့) 引越し可能 | ⬜ ဝန်ထမ်း ဆုံးဖြတ် |

### 7.3 案件 Card (user မြင်ရမည့် ပုံစံ)
```
💼 အလုပ်ခေါ်စာ အသစ်  |  UT-2608-001

🏭 အလုပ်: ကားပစ္စည်း စက်ရုံ — တပ်ဆင်ရေး
📍 နေရာ: 愛知県 豊田市
🕐 အချိန်: 日勤 08:00–17:00 (交替 မရှိ)
💴 လစာ: 【要確認】
🏠 အိမ်(寮): ရှိ — 【要確認】/လ
📋 လိုအပ်ချက်: 【要確認】visa · ဂျပန်စာ N5〜
👥 လိုအပ်သူ: 5 ဦး
📅 လျှောက်ရန် နောက်ဆုံးရက်: 2026/09/15

[▶️ ဒီအလုပ် လျှောက်မယ်]  [❓ မေးခွန်း ရှိတယ်]  [⏭ ဒီတစ်ခု မလိုချင်ဘူး]
```
> ⛔ 客先 (စက်ရုံ အမည်) မထည့်ရ။ ⛔ လစာကို ခန့်မှန်း မရေးရ — 案件DB ထဲက ဂဏန်းသာ။

### 7.4 `⏭ မလိုချင်ဘူး` နှိပ်လျှင်
တစ်ခါတည်း အကြောင်းရင်း မေး (နေရာ ဝေး / လစာ နည်း / အချိန် မကိုက် / အခြား) → 人材プール ထဲ မှတ်ထား → နောက်ပိုင်း matching တိုးတက်လာသည်။

## 8. 応募 → 面接 → 採用 Flow

### 8.1 `▶️ လျှောက်မယ်` နှိပ်လျှင်
- **人材プール ထဲ ရှိပြီးသား** → ⑤ 仕事説明 သို့ တိုက်ရိုက်
- **မရှိသေး** → §6 人材登録 flow → ပြီးလျှင် ဤ 案件 သို့ အလိုအလျောက် ပြန်လာ

### 8.2 ⑤ 仕事説明 (အလုပ်အကြောင်း ရှင်းပြခြင်း) — **မကျော်ရ**
Bot က 案件 အသေးစိတ် ပြပြီး အောက်ပါအတိုင်း အတည်ပြုချက် တောင်းရမည်:
```
အထက်က အလုပ် အချက်အလက်တွေကို ဖတ်ပြီးပြီလား? 🙏

[✅ ဖတ်ပြီးပြီ၊ လျှောက်ချင်ပါတယ်]
[❓ မေးစရာ ရှိသေးတယ်]   →  ဝန်ထမ်းသို့ (ticket)
[🔙 ပြန်စဉ်းစားမယ်]
```
> ⚠️ ဤအဆင့်သည် **တရားဝင် 労働条件明示 မဟုတ်ပါ** — ကြိုတင် ရှင်းပြချက်သာ။ တရားဝင် 就業条件明示書 ကို ⑧ 入社手続き တွင် စာဖြင့် ပေးရမည် (§12.1)။

### 8.3 応募 Status
```
応募 ──► 説明済 ──► 面接調整中 ──► 面接予定 ──► 選考中 ──┬─► 採用 ──► 入社予定 ──► 就業中
                                                        └─► 不採用 ──► 人材プールへ戻す
                            (どの段階でも) ──► 辞退 ──► 人材プールへ戻す
```

| Status | အဓိပ္ပါယ် | တာဝန် | SLA |
|---|---|---|---|
| `応募` | လျှောက်ထားပြီး | Bot → staff group | ချက်ချင်း |
| `説明済` | အလုပ်အကြောင်း ဖတ်ပြီး | Bot | ချက်ချင်း |
| `面接調整中` | ချိန်းဆိုနေ | ဝန်ထမ်း | ၂၄ နာရီ |
| `面接予定` | ရက်ချိန်းပြီး | Bot သတိပေး | 前日 + 当日朝 |
| `選考中` | ရလဒ် စောင့် | ဝန်ထမ်း | 【要確認】 |
| `採用` / `不採用` | ရလဒ် | ဝန်ထမ်း → Bot | ရလဒ်ရပြီး ၂၄ နာရီ |
| `入社予定` | 入社日 သတ်မှတ်ပြီး | ဝန်ထမ်း | |
| `就業中` | အလုပ် စပြီး | Bot follow-up (§10) | 3日/2週/1ヶ月 |
| `辞退` | ကိုယ်တိုင် ရုပ်သိမ်း | Bot → pool ပြန်ထား | |

**မဖြစ်မနေ စည်းမျဉ်း:** `不採用` ဖြစ်လျှင်လည်း **၂၄ နာရီအတွင်း အကြောင်းကြားရမည်**။ တိတ်ဆိတ်ခြင်းသည် 派遣 လုပ်ငန်းတွင် နာမည်ပျက်စေသည့် အကြီးဆုံး အကြောင်းရင်း ဖြစ်သည်။

## 12. Compliance & Guardrails

### 12.1 派遣 လုပ်ငန်း သီးသန့် 【要確認 — 社労士/ဥပဒေ အကြံပေးနှင့်】
- **労働条件明示 / 就業条件明示書** — 就業 မတိုင်မီ **စာဖြင့်** ပေးရမည်။ Bot ၏ 案件 card သည် ကြိုတင်ရှင်းပြချက်သာ ဖြစ်ပြီး တရားဝင် 明示 မဟုတ်ပါ။ ဤအချက်ကို ရောထွေးပြီး ပြဿနာ တက်တတ်သည်။
- **派遣禁止業務** — 港湾運送 · 建設 · 警備 · 医療 (အချို့) တို့သည် 派遣 တားမြစ်ထားသည်။ 案件 လက်ခံစဉ်ကတည်းက စစ်ရမည်။
- **求人広告 ဖော်ပြချက်** — လစာ/အချိန်/နေရာ ကို မှားယွင်း ဖော်ပြခြင်း (虚偽広告) သည် ဥပဒေချိုးဖောက်မှု ဖြစ်သည်။ 案件 card ၏ ဂဏန်းတိုင်း 案件DB မှသာ လာရမည် — bot က မခန့်မှန်းရ။
- **同一労働同一賃金** နှင့် ပတ်သက်၍ လစာ ပြောဆိုမှု — Tier 2 သာ။

### 12.2 ကိုယ်ရေးအချက်အလက်
1. ပထမဆုံး message တွင် consent စာကြောင်း:
   ```
   ※ သင်ပေးတဲ့ အချက်အလက်တွေကို အလုပ်ရှာဖွေရေး/လျှောက်ထားရေး
     အတွက်သာ သုံးပါမယ်။ ခွင့်ပြုချက်မရှိဘဲ တခြားသူ မမျှဝေပါဘူး။
   ```
2. Passport / မှတ်ပုံတင် / 在留カード / ဘဏ် — **bot ထဲ မကောက်ရ**
3. Staff group ထဲ ဓာတ်ပုံ/စာရွက် မတင်ရ — Notion ထဲသာ
4. 客先 (စက်ရုံ) အမည် — user ကို မပြရ 【要確認 — UT နှင့် NDA စည်းကမ်း】
5. ဒေတာ သိမ်းဆည်းချိန်: 【要確認】(အကြံပြု — နောက်ဆုံး ဆက်သွယ်ပြီး ၂ နှစ်)

### 12.3 ⚠️ ကျား/မ ဖြင့် စစ်ထုတ်ခြင်း
ဂျပန်တွင် **男女雇用機会均等法** အရ ကျား/မ ဖြင့် အလုပ်ခေါ်ခြင်း/စစ်ထုတ်ခြင်းသည် အခြေခံအားဖြင့် တားမြစ်ထားသည်။ 客先 က တောင်းဆိုသည့်တိုင် matching rule ထဲ ကျား/မ ကို **အလိုအလျောက် filter အဖြစ် မထည့်ရ**။ 【要確認 — ဥပဒေ အကြံပေးနှင့်】

### 12.4 Bot က ဘယ်တော့မှ မပြောရ
- "အလုပ် ရမှာ သေချာတယ်" / "採用 ဖြစ်မှာပါ"
- "visa ကျမယ်" / "ဒီ visa နဲ့ ရတယ်"
- "လစာ ¥XXX ရမယ်" (案件DB ထဲ မပါဘဲ)
- ဥပဒေ အကြံပေးချက် မည်သည့်ပုံစံမဆို
- ငွေ — bot ရော ဝန်ထမ်းရော ကိုယ်တိုင် မကိုင်ရ → ရုံးသို့ လမ်းညွှန်

## 13. KPI — လစဉ် ကြည့်ရမည်

| Metric | ဘာကို ပြောလဲ | ပစ်မှတ် |
|---|---|---|
| 人材プール အရေအတွက် (`求職中` သာ) | တကယ့် စွမ်းရည် | တိုးနေရမည် |
| Pool ၏ လတ်ဆတ်မှု (၃ လအတွင်း update) | pool တကယ် သုံးလို့ရလား | > 70% |
| 配信 → 応募 % | 案件 card ကောင်းလား / matching မှန်လား | > 20% |
| 応募 → 面接 % | ဝန်ထမ်း ဘက် လျင်မြန်မှု | > 60% |
| 面接 → 採用 % | ပို့သူ အရည်အသွေး | 【要確認】 |
| 採用 → 入社 % (辞退率) | ရှင်းပြချက် မှန်ကန်လား | > 90% |
| **入社 1ヶ月 定着率** | **အမြတ်ကို တိုက်ရိုက် သက်ရောက်** | > 85% |
| ခေါ်စာ ရ → လူပြည့် ကြာချိန် | စနစ်၏ အဓိက တန်ဖိုး | တိုနေရမည် |
| Bot က ပြီးအောင် ဖြေနိုင်သည့် % | Bot ကောင်းလား | > 50% |
| ပထမ လူသား ပြန်ဖြေချိန် | ဝန်ဆောင်မှု အရည်အသွေး | < ၂ နာရီ |

**လစဉ် review:** ① Bot မဖြေနိုင်ခဲ့သည့် မေးခွန်း Top 10 → FAQ ထဲ ထည့် ② `⏭ မလိုချင်ဘူး` အကြောင်းရင်း Top 5 → 案件 ရွေးချယ်မှု ပြင် ③ 辞退 အကြောင်းရင်း → 仕事説明 ပြင်

## 14. Phase 2 — တည်ဆောက်ရေး မှတ်စု (n8n)

> ဤအပိုင်းသည် နောက်တစ်ဆင့်အတွက်သာ။ ယခု အတည်ပြုရမည်မှာ §1–§13။

**Workflow ၄ ခု ခွဲရမည်** (တစ်ခုတည်းထဲ မထည့်ရ — ပြင်ရ ခက်သွားမည်):

| # | Workflow | Trigger | လုပ်ဆောင်ချက် |
|---|---|---|---|
| 1 | `bot-router` | Telegram Trigger | callback_data ခွဲ → သက်ဆိုင်ရာ flow |
| 2 | `candidate-intake` | (1) မှ | state machine (n8n static data) → 人材プール DB |
| 3 | `job-broadcast` | Notion 案件 `募集中` / manual | matching → ဝန်ထမ်း အတည်ပြု → sendMessage loop |
| 4 | `sla-reminder` | Schedule (နာရီစဉ်) | SLA လွန် ticket · 面接 前日 · visa 満了 90日 · pool 3ヶ月 update |

**Node ဆက်စပ်ပုံ (အကြမ်း):**
```
Telegram Trigger
  └─ Switch (JOBS / REGISTER / MYSTATUS / ASK / WORKER / HUMAN / JOB_<id>)
       ├─ JOBS     → Notion 案件DB (Status=募集中) → card loop
       ├─ REGISTER → state machine → Notion 人材プールDB create
       ├─ JOB_<id> → 人材 ရှိ? ─ ရှိ → 仕事説明 → 応募DB create → staff topic
       │                       └ မရှိ → REGISTER → ပြီးလျှင် ပြန်လာ
       ├─ MYSTATUS → Notion 応募DB lookup (Telegram User ID) → status card
       └─ ASK/HUMAN→ Notion お問い合わせDB create → staff topic ❓

Staff command (/claim /reply /interview /result) → Notion update → user ကို ပြန်ပို့
```

**လက်ရှိ ZAE စနစ်နှင့် ချိတ်ရန်:** Lead Pipeline ✅ Confirmed → Student Master auto-create ရှိပြီးသား pattern အတိုင်း — 人材プール နှင့် Student Master DB ကို ဖုန်းနံပါတ်ဖြင့် ချိတ်ဆက်နိုင်သည် (ကျောင်းသားဟောင်း → 派遣 လူစာရင်း သွားနိုင်သည့် လမ်းကြောင်း)။
